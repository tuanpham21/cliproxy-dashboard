# Journal idempotent reset redemptions across crashes

Every Reset Redemption Attempt uses a server-generated idempotency key and one owner-private active journal whose existence also serves as the per-OS-user Redemption Lease. Once consume reaches durable dispatch intent, loss of a terminal response creates an Ambiguous Redemption that never auto-expires and blocks all new redemptions for that OS user until the same attempt is resolved with the retained account-check digest, credit choice, and idempotency key. Terminal handling persists the terminal journal, writes a short-lived non-secret tombstone, emits an at-least-once secret-free Redemption Audit Event, then releases the lease and removes sensitive recovery state. Shared cross-user Codex state is unsupported. This adds local state and recovery complexity to prevent an irreversible provider credit from being consumed twice after timeouts, crashes, restarts, or concurrent dashboard processes.
