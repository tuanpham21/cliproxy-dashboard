# Domain Docs

This is a single-context repository.

## Before exploring

- Read root `CONTEXT.md`.
- Read relevant decisions in root `docs/adr/`.
- Use the glossary's canonical vocabulary in specs, issue titles, tests, and implementation plans.

## File structure

```text
/
├── CONTEXT.md
├── docs/adr/
└── docs/agents/
```

If a concept is missing from `CONTEXT.md`, resolve it through `/domain-modeling` before inventing a competing term. If work conflicts with an ADR, surface that conflict explicitly.
